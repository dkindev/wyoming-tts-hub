## The disagreement

`GLOSSARY.md` specifies the behaviour under **Language**:

> A spoken-language code (e.g., `ru`, `en`) that a **Model** declares it
> supports. A Wyoming client *may* send a **Language** with a synthesis request;
> when sent, the **TTS Engine Hub** validates it against the selected **Model**'s
> declared **Languages** and rejects the request on a mismatch. When omitted, the
> Hub resolves it from the **Model**'s sole declared **Language**, falling back to
> auto-detection when the **Model** declares `language_auto_detected`.

None of that happens. `TtsEngineHub.synthesize_pcm_chunks` accepts whatever
Language it is handed and passes it into the synthesis context
(`src/tts/engine_hub.py:51`) with no check. So a client asking for a Language the
Model cannot speak gets audio synthesized in the wrong language, with no error and
nothing in the log.

The second half of the sentence is out of scope here but worth recording:
`DetectLanguageMiddleware` (`src/tts/middleware.py:33`) assigns a hard-coded
`ctx.language = "ru"` to every request (`src/tts/middleware.py:38`). That satisfies
neither reading of the glossary — it neither derives the Language from the Model's
sole declared Language nor detects anything.

## Reproduction

`tests/test_engine_hub.py::TestLanguageValidation::test_language_the_model_does_not_declare_is_rejected`
requests `en` from a Model declaring only `ru`. It fails with `DID NOT RAISE
ValueError`, and the log shows the engine synthesizing the text anyway.

## Agent Brief

**Summary:** The TTS Engine Hub accepts any Language a client sends and
synthesizes it anyway, and the Language it does receive is a hard-coded literal
rather than anything derived from the Model. Resolve the Language from the
Model, validate it against the Model, and take the client's Language off the
wire.

**Current behavior:**

- The Hub performs no validation. A client asking for a Language the Model does
  not declare gets audio back, synthesized anyway, with no error and nothing in
  the log.
- The Wyoming handler never reads a Language from the request, so the Language
  handed to the Hub is always absent in production.
- A middleware assigns the literal `"ru"` to every request, overwriting
  whatever the client sent, regardless of which Model is serving the request.
- `Model.language_auto_detected` is parsed from configuration and read by
  nothing in the codebase.

**Desired behavior:**

Two distinct steps, in this order. They must not be conflated.

*Resolution* runs as a middleware, ahead of every stage that keys off the
Language (sentence splitting and text normalization both do):

- When the request carries no Language, the Model declares exactly one
  Language, and the Model does not auto-detect, the Model's sole Language
  becomes the request's Language.
- Otherwise the Language is left absent. In particular, a Model that declares
  several Languages is left alone, and a Model declaring
  `language_auto_detected` is left alone even when it declares exactly one
  Language.
- A Language supplied by the client is never overwritten.

*Validation* runs in the Hub, after the middleware chain has completed and
before the engine context is acquired:

- If a Language is present and the Model declares Languages, it must be one of
  them; otherwise reject with a `ValueError` naming the requested Language, the
  Model, and the Model's declared Languages.
- If a Language is present but the Model declares no Languages at all, there is
  nothing to validate against, so fall through to the next rule.
- In every remaining case — no Language was supplied, or the Model declares no
  Languages — the request proceeds only if the Model declares
  `language_auto_detected`. Otherwise reject with a `ValueError` naming the
  Model, its declared Languages, and that it does not auto-detect.
- Validation runs before the engine context is acquired, so a rejected request
  never loads or warms the Model.
- Validation inspects the Language as it stands *after* the middleware chain,
  not the raw request. A middleware is trusted to determine the Language.

*Wire surface:* the Wyoming handler should take the client's Language from the
request and pass it to the Hub's synthesis entry point. Note that the `wyoming`
library's `SynthesizeVoice.from_dict` discards `language` whenever `name` is
present, so the value must be read from the raw event payload rather than from
the parsed dataclass. The Language must also be captured for the streaming
path — the start event sets it, the stop event clears it — or a stale Language
leaks into the next streaming request.

`language_auto_detected` means exactly "this Model may be asked to synthesize
without a Language" and nothing more. When it does, no Language reaches the
engine. No detector is implemented.

The middleware no longer detects anything, so rename it to say it resolves.

**Key interfaces:**

- `SynthesisContext.language`: type unchanged (`str | None`); the incoming
  request Language on entry, the resolved Language on exit. Its contract is what
  changes.
- The Hub's synthesis entry point (`synthesize_pcm_chunks`): gains a `language`
  parameter of type `str | None`, forwarded into the synthesis context, plus
  the post-middleware validation step above.
- `Model.language_auto_detected: bool`: no type change, but becomes
  load-bearing for the first time.
- `Model.languages: list[str]`: unchanged; becomes the validation source of
  truth.
- Middleware chain: the Language-resolving middleware stays at the head.
- Wyoming handler: a helper that extracts a Language from a raw protocol
  event's `voice` payload, plus handler state carrying that Language across the
  streaming events.

**Acceptance criteria:**

- [x] A Language the Model does not declare is rejected; the error names the
      Language, the Model, and the Model's declared Languages, and nothing is
      synthesized
- [x] A declared Language reaches the engine unchanged
- [x] A request with no Language against a Model declaring exactly one Language
      synthesizes in that Language
- [x] A request with no Language against a Model declaring exactly one Language
      *and* `language_auto_detected` synthesizes, with no Language reaching the
      engine
- [x] A request with no Language against a Model declaring several Languages is
      rejected with a message naming the Model and every declared Language,
      unless the Model declares `language_auto_detected`
- [x] A Language supplied by a client survives the middleware chain unmodified
- [x] A rejected request never acquires an engine context
- [x] A Wyoming client that sends a Language beside the Voice name has that
      Language reach the synthesis entry point; a test covers this using a raw
      event payload, since the library's parsed dataclass cannot carry it
- [x] The streaming path carries the Language from the start event through to
      synthesis, and clears it on the stop event
- [x] The tests that currently pin the hard-coded Language are replaced by tests
      for the new resolution rules
- [x] Fixtures that build a Model with no declared Languages and send no
      Language are updated to declare a Language (or to wire the resolving
      middleware), so that they exercise a reachable configuration
- [x] The whole test suite passes, including the test that currently fails to
      pin this gap
- [x] `GLOSSARY.md`'s Language entry matches the implemented behavior: that the
      sole declared Language fills in only when the Model does not auto-detect,
      that a Model with no resolvable Language is an error naming its declared
      Languages, and that a Model declaring `language_auto_detected` may be
      asked to synthesize without one

**Out of scope:**

- Implementing language detection. `language_auto_detected` only permits
  synthesizing without a Language; no detector is built and the flag is not
  removed.
- Patching, pinning, or wrapping the `wyoming` library to preserve
  `SynthesizeVoice.language`. Read the raw event payload instead.
- Using the Language inside any TTS Engine. Engines discard it today and
  continue to.
- How a Voice's Languages are advertised over the Describe response.
- Language-code matching beyond exact string equality (no case folding, no
  `ru` / `ru-RU` tag matching).
